# Pausing and resuming the project

When you are not actively working on `portfolio-api`, you can tear down the AWS
resources so the monthly bill drops to **$0.00**, and later bring everything
back with a single command. The code stays in git — only the deployed
infrastructure disappears. **The API Key value is preserved**, so existing
clients (Postman, scripts) keep working after resume without any changes.

## Quick start

```powershell
npm run stack:pause     # saves state + tears everything down → $0/month
npm run stack:resume    # redeploys + restores the saved API Key
```

## What the scripts do

### `npm run stack:pause` → [scripts/pause-stack.ps1](../scripts/pause-stack.ps1)

1. Verifies AWS credentials (profile `portfolio-api`).
2. **Saves state** to `.stack-state/paused-state.dev.json` — the API Key value
   and the previous URL. The file is in `.gitignore` and never reaches the repo.
3. `cdk destroy PortfolioApiStack-<env>` — removes the Lambdas, API Gateway,
   IAM roles and CloudWatch log groups.
4. Empties the `cdk-hnb659fds-assets-<account>-eu-west-1` bucket so old
   deployment artifacts do not incur S3 charges.
5. Removes the `CDKToolkit` stack (CDK bootstrap) — by default. Use the
   `-KeepBootstrap` flag to keep it.

### `npm run stack:resume` → [scripts/resume-stack.ps1](../scripts/resume-stack.ps1)

1. Verifies AWS credentials.
2. `cdk bootstrap` (idempotent — recreates `CDKToolkit` if it is missing).
3. `cdk deploy PortfolioApiStack-<env> --require-approval never` — brings the
   stack up 1:1 from the current git state.
4. **Restores the API Key from the state file:** deletes the freshly generated
   key and creates a new one with the previously saved value, then attaches it
   to the Usage Plan. The state file is then deleted (consumed).
5. If the API Gateway URL has changed, prints the old and new URL.

## What is stored in `.stack-state/`

| Field | Purpose |
|---|---|
| `apiKeyValue` | The value of the `x-api-key` header. Restored 1:1 after `resume`, so your scripts/Postman need no update |
| `previousUrl` | The old API Gateway URL — so `resume` can tell you whether it changed |
| `accountId`, `region`, `env`, `pausedAt` | Metadata for diagnostics |

**Not stored:** the API Key ID, API Gateway ID, URL — AWS generates all of
these randomly on every deploy, so there is no point in keeping the old values.

## What disappears on pause

| Resource | Removed | Notes |
|---|---|---|
| `PortfolioApiStack-dev` (Lambdas, API Gateway, IAM, log groups) | yes | Recreated identically on resume |
| CDK artifacts in `cdk-hnb659fds-assets-<account>-eu-west-1` | yes | Old Lambda bundles stop incurring S3 storage charges |
| `CDKToolkit` stack (CDK bootstrap) | yes (by default) | `-KeepBootstrap` to keep it |
| API Key value | NO | Saved locally in `.stack-state/`, restored on `resume` |
| Code, git history, local configuration | no | Unchanged |

## What can still change

- **API Gateway URL** — AWS randomizes the ID on every deploy
  (`https://abc123.execute-api...` → `https://xyz789.execute-api...`). If you
  have the base URL in Postman or a script, you need to update it. The resume
  script prints the old and new URL for you.
- **Resource IDs inside AWS** (ARNs) — no impact on the client.

## Why "1:1" on resume

CDK is declarative — the code in `src/` IS the source of truth for the
infrastructure. `cdk deploy` synthesizes it into a CloudFormation template and
sends it to AWS. As long as the files in `src/` have not changed between
`pause` and `resume`, the output is deterministic — the same set of resources,
the same configs, the same logical names.

What **stays identical**:

- Resource names (`PortfolioApi-dev`, `PortfolioApiKey-dev`, etc.)
- Endpoints: `GET /api-models`, `POST /ibkr-csv-parser`
- Lambda configuration (runtime, memory, timeout, env vars)
- Usage Plan rate limiting and quota (10 req/s, 10k/day)
- **API Key value** (thanks to `.stack-state/`)

## Usage

### Pause

```powershell
# Default: dev, removes everything including the CDK bootstrap → $0.00/month
npm run stack:pause

# Keep the CDK bootstrap (in case something else starts using it)
./scripts/pause-stack.ps1 -KeepBootstrap

# Different env
./scripts/pause-stack.ps1 -Env test
```

### Resume

```powershell
# Default: dev — also restores the API Key value from .stack-state/
npm run stack:resume

# Different env
./scripts/resume-stack.ps1 -Env test
```

### Resume without state (fresh deploy)

If the `.stack-state/paused-state.dev.json` file does not exist (e.g. a clean
checkout, a deploy on a new machine), `resume` still works — it simply keeps
the new key generated by AWS and prints how to retrieve it.

## Requirements

- PowerShell 5.1+ (built into Windows)
- `aws` CLI with credentials for the `portfolio-api` profile
- Node.js / npx (for `cdk`)

No external dependencies such as `jq` — PowerShell has a native
`ConvertFrom-Json`.

## Expected costs

- **Paused (default, with bootstrap removed):** exactly $0.00/month.
- **Paused with `-KeepBootstrap`:** ~$0.00/month (the CDK bucket holds a few KB
  of metadata — a fraction of a cent).
- **Stack deployed, zero traffic:** ~$0.03–$0.10/month (S3 storage for CDK
  artifacts + CloudWatch Logs storage).

## Security

- The `.stack-state/paused-state.<env>.json` file contains the API key value
  **in plaintext**. The `.stack-state/` folder is in [.gitignore](../.gitignore) —
  never commit it.
- Keep the file only on the machine where you pause/resume. If you switch
  machines, move the file over a secure channel or accept that the key will be
  generated anew.
